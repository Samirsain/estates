# Member Profile — "Sales & Reference Trip" and "Royalty" sections

**What each section must show on the staff Member profile (`/members/[id]`).**

Sources: Change Pack §68 (Member Profile), §37 (Trip Reward), §47 (Royalty Buyback), §85 (holds), §70 (portal parity); SSOT §40–§66 (Trip), §72–§83 (Royalty).

Status column: ✅ shown today · ⚠️ shown but wrong or partial · ❌ missing.

---

## 1. Sales & Reference Trip

One block per **Project programme** (Project + Trip Programme Code), newest first.

### 1.1 Programme summary

| Field | What it shows | Status |
|---|---|---|
| Project · Programme Code | e.g. *Desert Square · TRIP-D* | ✅ |
| Rules | Target · Minimum Own · Maximum Reference · Trip Terms Version — from the open bucket, **or the last bucket when none is open** | ⚠️ hidden after a Trip is earned ("No open bucket") |
| Bucket | Open since *date*, or "No open bucket — next qualifying sale opens one" | ✅ |
| Progress | Counted toward target = Qualified Own + min(Qualified Reference, Max Reference), shown as *x / target* | ❌ |
| Pending Own Credits | Sales not yet at 100% (or approved Buyback) | ✅ |
| Qualified Own Credits | Ready, not yet used in a Trip | ✅ |
| Qualified Reference Credits | Counted up to Maximum Reference | ⚠️ labelled "banked" |
| Banked Reference | Qualified Reference beyond Maximum Reference, kept for a later Trip | ❌ |
| Held Credits | Held while the Member is Deactivated | ❌ |
| Expiry dates | Each qualified credit's expiry (12 months from qualification), nearest first | ⚠️ nearest only |
| Expired Credits | Count | ❌ |

## 2. Royalty

### 2.1 Royalty relationships owned (today: "Royalty linked Customers")

| Field | Status |
|---|---|
| Customer ID · name (staff view only — never in the portal) | ✅ |
| Relationship Final / Provisional | ✅ |
| First purchase that made it (Booking · Plot) and final date | ❌ |
| Royalty opportunity **UNUSED / CONSUMED** | ❌ |
| Summary line: *x final · y can still earn a Gift · z waiting for full payment* | ❌ |

### 2.2 Royalty Credits (one card per Gift)

| Field | Status |
|---|---|
| Customer ID · name and the trigger Booking | ✅ |
| Qualified by — 100% Payment Received / Approved Buyback (after ≥25%) | ✅ |
| Eligible on | ✅ |
| Programme Version — *RGP-01 v1* · catalogue · terms | ⚠️ reference only, no version |
| State — Eligible / Selected / Ordered / Delivered / Reversed | ✅ |
| Gift reference · recipient and relation · NT10 approval for non-family | ✅ |
| Order reference · ordered on | ⚠️ date missing |
| Delivered on · delivery reference | ⚠️ reference missing |
| Fulfilment hold — incl. *Waiting for Stable Buyback Completion* (CP §47) | ✅ |
| Reversal reason | ✅ |
| Actions: Record Gift → Order → Delivered | ✅ |

**Empty state** (today: "No Royalty Credit yet."): explain the rule — *"A Gift is earned when a final linked Customer's first Club-direct purchase is paid in full (or an approved Buyback after 25%). y relationships can still earn one."* ⚠️

## 3. Never show (CP §68, §70)

- Any rupee value, Trip cost, Gift cost or Project economics.
- Internal Accounts notes.
- Customers' full KYC or bank details.
