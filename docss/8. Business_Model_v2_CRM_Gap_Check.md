## 4. Not built — new v2 work

### 4.1 Trip Programme + Reference Credit (CP §9, §22–§39, §76.1–2; UAT TRP 28, REF 12)
- Trip fields on the Project Settings Version: enabled, total target, minimum Own, maximum Reference, Terms ref, cut-off, wind-down deadline.
- Version-linked inventory eligibility (`TripProgrammeInventoryRule`). Booking snapshot gets the Trip fields.
- `TripCredit` (Own/Reference; Pending → Qualified → Allocated → Used / Held / Reversed / Expired) with the unique key Member + Plot + programme identity.
- `TripBucket` that opens on the first Pending credit and freezes target/composition/terms; an empty bucket closes if its opening credit reverses.
- Deterministic FIFO allocation; Earned → Deficient → backfill.
- `TripReward` fulfilment (Earned → Booking Requested → Booked → Travelled) and nominee.
- Reference opportunity per introduced Member: consumed atomically under a lock; tie-break by earliest qualification, then lower Booking Number. Self-purchase and Trip-disabled Projects don't consume it. A Deactivated inviter's credit is created but held.
- Jobs: 12-month credit expiry, programme wind-down.
- Tasks: NT03, NT04, NT05.

### 4.2 Royalty Relationship Reward (CP §40–§49; UAT ROY 18)
- Relationship record (see D8), one per Primary Customer.
- Reward trigger: the Customer's later purchase with final Sold By = 3% Club, relationship Final, opportunity unused, Gift Programme live.
- `RoyaltyCredit` (Eligible / On Hold / Selected / Ordered / Delivered / Reversed). One per opportunity, with no rate or amount.
- Gift Programme Version frozen on the approved reward-triggering Booking Request; MD activation (NT07); fulfilment (NT06); nominee (NT10).

### 4.3 Buyback reward integration (CP §50, §51, §83, §84; UAT BB 14)
- The 25% source-payment gate exists for Loyalty and the Royalty link. It must also cover Own-Sale, Reference and Royalty Credit.
- **Stable Buyback Completion** = Approved + Payment Given 100% + not unwound + document return done. Document return is only a task today (`BUYBACK_PAPERS`, `acquisition-service.ts:881`) and is not stored as a completed fact.
- Buyback-qualified Trip/Gift fulfilment stays held until Stable Completion. An unwind reverses Buyback-only qualification but never reopens a Travelled/Delivered reward.

### 4.4 Recovery and controls (CP §54–§58, §78, §85, §86; UAT CTL 12)
- **Recovery:** Recovery Outstanding record, external reference, 15-day deadline, set-off, block on new cash payouts, hold on Trip/Gift fulfilment, deactivation link. Tasks T22 and T23.
- **Circumvention review (NT08):** triggered by shared bank, mobile, address or a related-party link.
- **Bank uniqueness:** one verified account = one Person, with a joint-account exception. `BankDetail` stores only cipher + last four (`schema.prisma:1498`), so a normalised blind index is needed to detect duplicates.
- **Staff / staff-relative conflict (NT09):** disclosure, MD approval, and no self-approval.
- **Fulfilment hold engine:** the 8 hold reasons in CP §85, released on events. Reactivation re-evaluates held rewards (§86).
- **Person Merge (§87):** no duplicate inviter, Reference opportunity, Royalty relationship/opportunity, Trip Credit or Recovery. Today merge only consolidates the closing-Loyalty count.

### 4.5 Screens, reports, jobs (CP §63–§76, §90; UAT TSK 12, VIS 12, SYS 12)
- Dashboard cards from §67.
- Member profile: Trip, Royalty and Recovery sections, plus Reference summary.
- Customer profile: repeat-purchase history, Royalty opportunity UNUSED/CONSUMED, closer KYC eligibility.
- Member portal: frozen Direct rate per deal, Trip progress, Royalty Credit state, safe hold indicator.
- Reports: Trip, Reference, Royalty, split Loyalty.
- Scheduled jobs: settings activation, credit expiry, wind-down, fulfilment release, Recovery recheck.

## 5. Questions that need the Owner's decision

The Change Pack (§2) says a genuine ambiguity becomes a numbered Change Request rather than a developer's choice.

| # | Question | Recommended answer |
|---|---|---|
| **Q1** | The CRM has **one Plot per Booking** (`schema.prisma:1034`). UAT TRP-03/04 and the Reference "multi-unit first sale" rule describe one Booking containing several units. | Keep one Plot per Booking. Each Booking gives the seller one Own-Sale Credit. The inviter's Reference opportunity is consumed by the first qualifying Booking, so a buyer taking 3 units still gives only one Reference Credit. Rewrite TRP-03/04 as "three Bookings". No schema change. |
| **Q2** | The SSOT freezes the inviter "at Membership Application submission", but the CRM has no application step: Admin/MD activates and records the inviter in one action. | Treat activation as the application submission for the freeze. Add an application stage only if you want one. |
| **Q3** | When is "final Sold By Customer" checked for KYC, Terms and < 3 (D1, D2)? | Check at Booking Request submission, again at Accounts approval (when Sold By becomes final), and on Sold By Correction. |
| **Q4** | Post-programme **subdivision** inheritance (CP §9 `parentCreditPoolPlotId`, SSOT §44): the CRM's Plot has no parent/child link. | Leave it out until the CRM supports subdividing a Plot. Note it as a known limit in the Trip Terms. |
